# 测试与验收记录

本目录保存可长期阅读、可追溯的测试规则和结论。机器生成的日志、下载文件、截图和 JSON 明细写入 `reports/test-runs/<run-id>-<suite>/`，该目录不提交 Git；稳定结论必须归纳到 [持续测试日志](test-log.md)，不能只留下一个无人解释的原始报告。

## 分层标准

| 层级 | 目的 | 通过含义 |
| --- | --- | --- |
| 单元/集成测试 | 验证确定性代码和接口契约 | 已覆盖的代码路径符合断言，不代表业务验收通过 |
| 真实模型 API 验收 | 验证模型、API、Worker 和文件交付闭环 | 测试断言和确定性质量门禁全部通过 |
| `tests/manual` 全量验收 | 验证 15 套仓库材料的业务结果 | 任务成功、内容/数值/公式/结构/证据均满足要求 |
| Web/Android 验收 | 验证客户端契约和跨端行为 | 真实上传、状态、下载和历史记录可用且语义一致 |

以下情况不得记为成功：

- 生成了文件，但核心字段、数值或公式为空；
- 将 `None` 单元格计入“已写入”；
- 操作目标未命中，只因替换文本在别处出现就声称幂等成功；
- 模型校验返回失败，却无依据地降级为 warning；
- 为迎合错误期望值而破坏可由源材料证明的业务计算。

## 执行命令

基础检查：

```powershell
./scripts/test.ps1
```

运行 15 套真实 API 材料：

```powershell
$env:ACCEPTANCE_EMAIL = "专用测试账号"
$env:ACCEPTANCE_PASSWORD = "专用测试密码"
python scripts/run_manual_acceptance.py --run-id 20260801-after-business-refactor
```

运行器直接提交 `tests/manual` 中的源材料、模板和任务要求；期望文件只用于下载后的比较。每次执行生成独立目录和 `results.json`，不得覆盖旧运行。

## 记录要求

每次准备发布或修改核心 AI 逻辑后，在 [持续测试日志](test-log.md) 追加一条记录，至少包含提交、环境、模型、各层结果、已知限制和结论。发现测试材料矛盾时记录到 [测试材料问题](fixture-issues.md)，不得在运行器中偷偷适配。
