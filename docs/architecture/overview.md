# 系统架构

## 总体结构

```mermaid
flowchart LR
    Web["Vue Web"] -->|"HTTPS"| Gateway["Nginx 网关"]
    Android["Android 原生端"] -->|"HTTPS / JSON / 文件上传"| Gateway
    Gateway -->|"/api/ 反向代理"| API["FastAPI API"]
    API --> PG[("PostgreSQL")]
    API --> Redis[("Redis")]
    Redis --> Worker["Celery Worker"]
    Scheduler["Celery Beat 调度器"] --> Redis
    Worker --> Engine["文档、提取与表格引擎"]
    Worker --> PG
    Worker --> Files[("任务文件卷")]
    Worker --> Webhook["签名 Webhook"]
    Engine --> LLM["模型供应商"]
    API --> Knowledge["混合检索与证据知识图谱"]
    Knowledge --> PG
```

Web 与 Android 是同一业务平台的两个客户端，共用认证、任务、文档工作台、团队模板和企业平台接口。客户端只负责交互、展示与短期编辑状态，任务、模板、文档、知识图谱与企业配置均以服务端持久化数据为准。Web 使用服务端签发的 HttpOnly 会话 Cookie，Android 使用系统安全存储中的 Bearer Token；两种凭据均由同一鉴权依赖校验。

## 组件职责边界

| 组件 | 职责范围 | 非职责范围 |
| --- | --- | --- |
| Web / Android | 输入校验、交互状态、文件选择、任务展示与下载 | 直接访问数据库，或在客户端保存服务端密钥 |
| Nginx | TLS 终止、静态资源、`/api/` 反向代理、缓存、上传限制和安全响应头 | 执行业务逻辑或绕过 API 鉴权 |
| FastAPI API | 鉴权、所有权隔离、参数与文件校验、任务创建和查询 | 在 HTTP 请求中同步执行耗时 AI 任务 |
| Celery Worker | 文档处理、模型调用、表格计算、质量校验和结果持久化 | 接受未经 API 校验的外部请求 |
| Scheduler | 扫描到期计划并投递任务 | 执行业务处理或维护第二套调度状态 |
| PostgreSQL | 用户、组织、任务、审计和业务元数据 | 保存 Redis 队列状态 |
| Redis | Celery 队列、任务结果后端与生产环境共享限流计数 | 作为长期业务事实来源 |
| 任务文件卷 | 保存上传文件和生成交付物 | 替代数据库中的权限和生命周期记录 |
| 模型供应商 | 按受控提示完成推理 | 决定权限、任务状态或最终确定性校验结果 |

## 请求与任务生命周期

1. 客户端提交认证信息、任务参数和文件；
2. API 完成鉴权、用户或组织隔离、文件安全校验与参数校验；
3. API 写入任务记录并将异步任务投递至 Redis；
4. Worker 执行真实处理节点，并写入进度、时间线、证据、质量结果和错误；
5. 客户端轮询或刷新任务状态，并在成功后下载交付物；
6. 需要外部集成时，Worker 按配置投递带签名的 Webhook。

耗时 AI 操作不占用 HTTP 请求生命周期。任务状态按 `queued → running → succeeded/failed/cancelled` 变化，进度只在处理步骤状态变化时更新，不按等待时间模拟。

任务记录、组织归属、周期额度占用和审计日志在同一数据库事务中提交。文档编辑、信息提取、表格填充、手动工作流和计划任务使用统一额度规则；额度不足时不创建孤立任务，也不进入 Celery 队列。套餐与额度仅允许平台管理员按授权调整，组织所有者不能自行提升套餐。

## 后端分层

```text
docnexus/
|-- api/                     # HTTP 路由、鉴权与请求依赖
|-- ai/                      # 文档、提取、表格、RAG 与图谱能力
|-- core/                    # 配置、安全、限流和可观测性
|-- db/                      # SQLAlchemy 模型和会话
|-- repositories/            # 带所有权隔离的数据访问
|-- schemas/                 # HTTP 传输契约
|-- services/                # 文件解析、质量、调度、企业与回调服务
|-- worker/                  # Celery 任务执行器
`-- main.py                  # ASGI 应用入口
```

数据库结构由 `backend/alembic` 中的迁移脚本统一管理。下载、查询、取消、重试和删除操作均须重新校验资源所有权，不得仅依据客户端传入的资源 ID 授权。

## 知识与证据架构

知识库采用“文档片段、规范实体、类型化关系、来源证据”四层结构。文档加入知识库后生成检索片段；结构化提取完成后，Worker 将最新字段同步为持久化实体和关系。相同类型与规范名称的实体在单个知识库内归并，其来源文档、原文片段、字段名称、位置和置信度分别保存，不因实体归并而覆盖。

检索首先计算关键词和本地特征向量相关度，再以查询命中的实体为起点扩展一跳关系。相关图谱路径只作为召回排序的可解释增强信号，最终结果仍返回原始文档片段和引用位置。当前实现不将词法特征向量描述为语义 Embedding，也不允许脱离证据依据图关系生成事实。

## 客户端分层

- Web：路由页面调用 Pinia Store 或 API 模块，HTTP 客户端统一处理令牌和错误；
- Android：Composable 只表达 UI 和用户事件，ViewModel 管理状态，Repository 负责远程数据访问；
- 两端应对齐业务能力和视觉语言，但遵循各平台的导航、权限、文件选择和生命周期规范。

## 网络环境

- Web 开发服务器通过 Vite 代理访问 API；
- Android 模拟器使用 `10.0.2.2` 访问宿主机；
- Android 真机本地调试可使用 `adb reverse`，仅限开发连接；
- FastAPI 将全部公开业务路由原生注册在 `/api/` 下，Nginx 保留路径并透明转发；
- 生产 Web 与 Android 必须使用受信任证书的 HTTPS API，不应依赖局域网地址或 ADB 隧道。

## 可靠性与可观测性

Worker 使用软硬超时、延迟确认和有限重试；容器异常退出后，未确认消息可重新投递。Webhook 入队失败和短暂投递失败会持久化，并由调度器周期性恢复。生产限流使用 Redis 在 API 实例间共享计数；Redis 不可用时受保护端点明确返回服务不可用，避免安全控制静默失效。健康检查区分存活与就绪状态，Prometheus 指标通过 `/api/metrics` 暴露。日志、任务时间线与 Webhook 投递记录共同用于故障定位。
